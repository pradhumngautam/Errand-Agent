# Errand Agent

A chat agent that arranges home-service errands (plumber, electrician, AC servicing, carpenter, cleaning) against mock providers. It collects only the details it's missing, compares providers, and asks for approval before anything consequential. Approval is **enforced in code**: the model has no tool that books, cancels or reschedules. Bookings are idempotent across retries and restarts, and success is reported only after it is verified with the provider.

## Quick start

Requires Python 3.12+ and [uv](https://docs.astral.sh/uv/).

```bash
uv sync
uv run pytest            # unit tests + the full eval suite (offline, ~5 s); regenerates evals/RESULTS.md
uv run errand-eval       # eval suite only, prints a pass/fail line per scenario
```

Tests and evals need **no API key and no network**. They run against a scripted model and a seeded mock provider.

### Run the live demo

Add **one** API key to `.env`. That's all the live demo needs:

```bash
cp .env.example .env     # then set GEMINI_API_KEY (free: https://aistudio.google.com/apikey)
                         # or OPENROUTER_API_KEY
uv run errand-web        # http://127.0.0.1:8000 (set PORT to change)
```

The web UI shows the chat on the left and the live trace on the right, with tabs for state and bookings, and for memory. Each agent reply has a collapsible work panel: context sent, model calls, tool calls, guards and state changes, streamed as they happen. **Demo controls** let you force failures during a live run:

| Control | Effect |
|---|---|
| Arm `timeout_booked` / `slot_taken` / … | The next `book()` returns that outcome |
| Price drift | The next hold quotes more than the search price |
| +11 min | Moves the clock past the 10-minute hold |
| Provider cancels | The provider cancels your latest booking; the watcher notices on its own |
| Reset | Fresh seeded state |

A terminal chat is also available: `uv run errand-chat` (`/approve <id>`, `/poll`, `/cancel-by-provider <id>`, `/memories`).

### Model providers

The provider is picked from `.env` at startup: **OpenRouter if `OPENROUTER_API_KEY` is set, otherwise Gemini if `GEMINI_API_KEY` is set**. Set `LLM_PROVIDER` to force one.

| `LLM_PROVIDER` | Needs | Notes |
|---|---|---|
| `gemini` | `GEMINI_API_KEY` (free tier works) | Probes for a working Flash model and fails over on quota. `GEMINI_MODEL` to override. |
| `openrouter` | `OPENROUTER_API_KEY` | Streams reasoning; reports real per-call cost. `OPENROUTER_MODEL` to override (default `google/gemini-3.6-flash`). |
| `claude_cli` | A locally installed, signed-in `claude` CLI | Optional no-key fallback, used only when no API key is set. Runs `claude -p` as a plain model: built-in tools, MCP and settings off; actions requested through a JSON schema. `CLAUDE_CLI_MODEL` (default `haiku`). |

The agent loop, approvals, guards and traces are identical across providers; only the transport differs.

### Record the end-to-end trace

```bash
uv run python scripts/record_trace.py             # live model: request -> hold -> "yes" -> book() times out but booked
uv run python scripts/record_trace.py --scripted  # same flow, offline
```

## How it works

```text
user ─► Agent.handle_message ─► ContextBuilder (budgeted prompt + manifest)
                                   │
                                   ▼
                                 model ──► intent tools: update_request, search_providers, get_provider,
                                   │       hold_slot, request_approval, remember/forget/list/confirm memory
                                   │              │
                                   │              ├─ ReviewAnalyzer (2nd agent: raw reviews -> digest)
                                   │              └─ ToolGateway (budget, tracing) ─► mock provider (8 tools)
                                   ▼
                        approval card (fingerprint of action, provider, slot, price)
user "yes" / button ─► ApprovalManager.verify ─► ActionExecutor (write-ahead log, derived key,
                                                   verify via get_booking_status, recover on startup)
background watcher ─► poll_events: provider cancelled? -> replacement -> fresh approval card
```

| Path | What it holds |
|---|---|
| `src/errand_agent/agent.py` | Turn handling, model loop, confirmation, proactive watcher, claim guard |
| `workflow.py` | Explicit state machine and typed errand request (merge-only corrections, `missing()`) |
| `approvals.py` | Approval lifecycle, material-details fingerprint, bare-affirmative parser |
| `executor.py` | Book/cancel/reschedule with write-ahead log, idempotency keys, verification, `recover()` |
| `tools.py` | Model-facing tools and their guards (grounded intent, downgrading unstated preferences, unknown tools) |
| `memory.py`, `context.py` | Explicit/inferred memory with supersede/forget; token-budgeted context with a per-call manifest |
| `reviews.py` | Review checker that keeps raw provider text away from the main model |
| `budget.py`, `gateway.py`, `tracing.py` | Hard limits, the single choke point for tool calls, JSONL traces |
| `mocks/` | Deterministic SQLite mock of the 8 provider tools with configurable failure scenarios |
| `llm/` | Provider-neutral client protocol, scripted/recorded models, live adapters |
| `evals/` | Harness, simulated users, invariants, scenarios, table generator |
| `web/` | FastAPI app (SSE streaming) and single-page UI |

## Evals

`src/errand_agent/evals/` runs 31 scenarios, each with a fresh sandbox, a fake clock, a seeded provider and a scripted model. The model is deliberately untrusted: scenarios script it to call tools it shouldn't, fall for injected reviews, and claim success it never had. Simulated users answer only what the agent asks and confirm only the cards they want.

Each scenario asserts its own outcome. Then **8 global invariants** are checked against ground truth (the provider's booking table, the approvals and write-ahead log, and the trace files):

- no side effect without a valid approval
- each booking matches the approved provider, slot and price
- no duplicate bookings
- success is reported only when verified
- raw review text never reaches the model
- forgotten or unconfirmed facts are never in a prompt (audited at every model call)
- context stays within the token budget
- every run is bounded and every turn gets a reply

`tests/test_evals.py` also breaks each rule behind the agent's back to prove the matching invariant notices.

Coverage includes adversarial users, prompt injection, changed price or slot after approval, timeout after success, slot conflict, repeated confirmation, memory correction and forgetting, restart mid-booking (before and after the provider call), proactive cancellation, the context budget with 53 memories and 180 past messages, turn and tool-call limits, and tool and model failures.
